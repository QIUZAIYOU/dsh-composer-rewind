# 提示词历史 · Prompt Vault

给 DeepSeek Harness Web UI 的输入框加一份「本地草稿历史」：你在输入框里写下的内容会被静默记录，写错了、清空了、刷新了，都能一键找回。

它是一个 Cordis 插件包（Host 半边为空壳，界面全部由 Client 半边渲染），装在 Harness 里就是输入框左侧工具行上的一枚小按钮。

## 装了什么

| 位置 | 作用 |
| --- | --- |
| `conversation.input.left` | 输入框工具行左侧一枚历史按钮（带条数角标），旁边一个不可见的记录器 |
| `shell.overlay` | 点击按钮后浮出的居中面板：搜索、插入、复制、删除、清空 |

## 行为

- **自动记录**：停止输入约 900ms 后记录一次；页面隐藏 / 卸载（刷新、关标签、崩溃恢复走同一路径）时会抢写一次。
- **去重**：内容与最近一条相同则只更新时间，不重复堆叠；完全相同的旧内容被再次写入时会被提到最前面。
- **上限**：最多 300 条，超出丢最旧。空白内容不记录。
- **插入**：把历史内容写回输入框，**不会自动发送**，你可以先改再发。
- **快捷键**：面板内 `↑` / `↓` 选择、`Enter` 插入、`Esc` 关闭；搜索框有焦点时同样生效。插件本身不注册全局快捷键（Harness 没有给插件留下全局热键位，需要的话可以在后续版本接入 Harness 的 shortcuts 注册）。

## 数据存在哪

浏览器 `localStorage`，键名 `dsh-prompt-vault:v1`，只在这台机器、这个浏览器配置里，不上传、不写日志、不进会话记录。清空面板里的「清空」会直接清掉 localStorage 中的历史。

> 已知取舍：`localStorage` 是**每个 Web GUI origin 一份**。换端口（`127.0.0.1:54798` → 别的端口）会被浏览器当成另一个站点，历史不共享；换浏览器同理。

## 已知限制

1. **不记录“已发送”的历史**：它记的是输入框草稿（含发出去之前那一刻的内容）。要按会话回看自己发过什么，应读会话日志，而不是这个插件。
2. **只在输入框里工作**：Harness 的 composer 是唯一来源；不监控网页里的其它输入框（原浏览器扩展方案已废弃，见仓库 `prompt-history-extension/`）。
3. **面板不在 composer 内部**：挂在 `shell.overlay`，位置是屏幕居中的浮层，不随输入框位置浮动。
4. **没有全局快捷键**：见上。
5. **无渲染自检能力**：开发环境里没有可控浏览器，样式与交互只用静态检查验证过，实际观感以刷新后的界面为准。

## 开发

```
# 安装（在插件目录所在机器上）
plugin_manager install_bundle  target=<本目录绝对路径>

# 改完 client.js 后
#   1. 静态检查
node --check client.js
#   2. 刷新 Web GUI 页面（client 插件按模块热更，但只有 pnpm run dev:web 在跑时才会自动重载）
```

样式只用 `--dsw-alias-*` / `--dsw-elevation-*` 主题 token，不引入外部样式表，不依赖任何 Harness Client 包（除 `react` 由宿主提供）。

## 设计取舍

- **为什么是插件而不是浏览器扩展**：目标是 Harness 自己的输入框（slot + composer 状态），扩展拿不到 `inputActions.setDraft` 这类能力，只能模拟键盘，不可靠。
- **为什么先 localStorage**：Harness 的 Host `ctx.storage` 只挂了 backend、没有现成 form，接入要自己定 backend 名与 schema；v1 先用页内存储把行为做对，Host 侧持久化留作下一步。
- **为什么 Host 半边是空壳**：目前没有需要在 Host 跑的逻辑；保留 `apply()` 是为了将来挂 `prompt_vault` 工具给 Agent 读同一份历史（见下）。
